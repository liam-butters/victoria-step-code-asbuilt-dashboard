Methodology & caveats

This dashboard extracts step_code_reports.xlsx (an independently-collected set of as-built BC Energy Step Code reports for Victoria) and compares it against the main BC Energy Step Code Dashboard (built from the NRCan evaluation database), filtered to city = Victoria. The goal is to check whether the NRCan-based dashboard, filtered to Victoria, gives a representative view of this separately-sourced data.

Column mapping

  • Homes count / Dwelling Units — a row in this workbook can represent a whole block of identical attached units (e.g. a row of townhomes modeled once in HOT2000 and applied to all of them), not a single house. Every per-home metric and the overall homes count are weighted by this workbook's Dwelling Units column, so this dashboard's figures are on the same per-home basis as the main dashboard's own per-house data. Floor area and GHGs are each stored as a total for the whole row (e.g. a 6-unit block's combined floor area and combined GHGs), so each is divided by Dwelling Units first to get a true per-home value, then weighted the same way as every other metric. Every other metric here is already a per-home value, since it comes from the single HOT2000 model that stands for every identical unit in the block. Single Detached, Detached w/Secondary Suite and Single Detached w/Secondary Suite rows are always treated as a single entry regardless of their own Dwelling Units value - never divided or weighted by it - because a secondary suite is recorded in the NRCan dataset as an attribute of one entry (Dwelling Units = 2), not two separate homes; a true multi-unit block (Double/Semi-detached (non-MURB), Row House (non-MURB), Multi-plex (non-MURB)) is still divided and weighted by Dwelling Units as described above, since the NRCan dataset does record those as one entry per unit. Rows with more than 2 Dwelling Units (6-14 unit MURB/rowhouse blocks) are included and weighted the same way as every other row - but the main dashboard's own Victoria/Saanich data has no row above 2 Dwelling Units at all, so these larger blocks have no directly comparable population on the NRCan side, and because every per-home average is weighted by Dwelling Units, a handful of such rows (modern, all-electric, so unusually efficient) can pull this spreadsheet's averages further from the NRCan baseline than the underlying difference in typical homes would suggest - see "Other caveats" below.
  • Row completeness — a row missing any metric shown on this dashboard is excluded from every metric's average, not just the one it's missing, so every row contributing to "Avg. MEUI" also contributes to "Avg. TEDI", "Avg. GHGs", etc. - no metric silently draws from a different, possibly-unrepresentative subset of rows than the others. NLR is the one exception: it's far less consistently reported than everything else here, so a row missing only NLR still counts for every other metric - it just can't contribute to the NLR average itself. In this workbook, NLR turns out to be reported exclusively on rows that are also missing Conditioned Floor Area (the "2 m²" placeholder rows excluded above) - so once those rows are excluded, no row in this dashboard has both NLR and a valid floor area/GHGs/etc., and "Avg. NLR" shows no data at all rather than a potentially misleading number computed from a handful of otherwise-incomplete rows.
  • MEUI / TEDI / ACH50 / NLA / NLR — taken directly from this workbook's MEUI As-Built, TEDI As-Built, ACH@50Pa As-Built, NLA@10Pa As-Built and NLR As-Built columns (same quantities, same units as the main dashboard).
  • Floor area — this workbook's Conditioned Floor Area (m2), compared against the main dashboard's HEATEDFLOORAREA. The two aren't guaranteed to be defined identically, though they're normally close.
  • GHGs / GHG intensity — not taken from this workbook's Zero Carbon framework GHG columns (ZC Total GHG Result / ZC GHG per m2 Result), which are unreliable for reports pulled from the 2018-era compliance report format used here (some rows had values three orders of magnitude too high). Instead, GHGs are calculated directly from this workbook's as-built fuel consumption — F Electricity As-Built (GJ/yr) × 3.06 + F Natural Gas As-Built (GJ/yr) × 50 (kg CO2e/GJ each) — the same way the underlying compliance reports derive it. GHG intensity divides that whole-row total by the row's (also whole-row) floor area, so it's unaffected by Dwelling Units either way; the "GHGs" figure shown here is that same whole-row total divided by Dwelling Units, same as floor area, so it's on the same per-home basis as every other metric (see Column mapping above). Rows whose compliance report had no fuel breakdown at all are left out rather than estimated. Note: the sibling Saanich dashboard calculates this differently — its compliance reports are all the modern format, so its Zero Carbon GHG column is trusted directly rather than recalculated from fuel use. The two GHG figures aren't derived the same way and shouldn't be assumed directly comparable between the two spreadsheets.
  • Overall step achieved — this workbook's Step As-Built, compared against the main dashboard's Step Achieved.
  • Building type exclusions — rows whose Building Type is Low-Rise MURB, Low-Rise (MURB), or Other are excluded from this dashboard entirely (4 of this workbook's as-built rows), rather than counted like every other building type.
  • House vs. multi-unit building — this workbook's granular Building Type values are grouped into "House" vs. "Multi-unit: whole building" (any type containing "MURB") to match the main dashboard's own two-bucket convention.

No equivalent available

  • MEUI/TEDI % improvement over the CSA F280 reference house — this workbook has no reference-house baseline column at all (it reports Required / Proposed / As-Built, not a Reference tier), so this can't be derived here.
  • Envelope RSI (ceiling, wall, foundation), heating/cooling system type and fuel, climate zone, and cooling design load have no columns in this workbook.

Other caveats

  • Sample sizes are very different (roughly — homes here, the same count for every metric except NLR, vs. a few hundred in the main dashboard's Victoria slice) — this file's averages are far more sensitive to any single project.
  • Only rows with Report Stage = As-Built are included (the handful of Pre-Construction rows have no as-built data to compare), and rows missing any metric other than NLR are excluded (see Column mapping and Row completeness above).
  • A handful of this workbook's rows are 6-14 unit MURB/rowhouse blocks, which the main NRCan-based dashboard's own Victoria/Saanich data has no equivalent of at all (it tops out at 2 Dwelling Units per row) - see Column mapping above.
  • A few municipality values in this workbook are typos of "Victoria" (e.g. "Victoira", "Vcitora") and have been normalized. Every row that passes the Report Stage filter above is included in the totals below, including the one Nanaimo and one Saanich row — if they're in this workbook, they're treated as applicable to this area rather than excluded.

Year basis, year-matching and mean/median

  • The main NRCan dashboard can assign each home's year two different ways — year built or entry date (when the evaluation was logged) — and the two give meaningfully different year coverage. The "NRCan year basis" dropdown above switches which one the comparison tables, trend charts and category-mix charts all use; it does not change anything about this spreadsheet's own data.
  • The comparison table restricts the NRCan baseline to only the years this spreadsheet itself has data for (shown in the note above the comparison table), so the "NRCan dashboard" column is a genuine apples-to-apples time comparison rather than an average across every year NRCan has — which, for a dataset of homes that generally get more efficient over time, would otherwise skew the baseline toward NRCan's earlier, less-efficient years. The year-by-year trend charts below only plot years where both this spreadsheet and the NRCan baseline have data - a year with data on only one side is left out rather than shown with a line that drops to nothing. The category-mix charts (Step Code achieved, house type) still use the whole NRCan dataset, not just matched years, since those are breakdowns of composition rather than of a metric average.
  • The "Statistic" dropdown switches every average above between the mean and the median of the underlying per-home values, for both this spreadsheet and the NRCan baseline.
